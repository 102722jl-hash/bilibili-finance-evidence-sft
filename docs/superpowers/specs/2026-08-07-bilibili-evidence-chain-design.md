# 巫师财经公开视频事件与推理链数据集设计

日期：2026-08-07
状态：设计已确认，待实现

## 1. 目标与边界

本项目从 UP 主巫师财经的公开视频及其同步图文稿中，抽取“文章/视频如何讲述一个事件、如何从事实推导结论”的可审计结构。

首轮处理 10 条资本市场与公司案例类视频。样本优先覆盖不同机制，而不是按播放量简单排序，候选主题包括：徐翔、万科争夺战、世纪白银操纵案、上市公司财务造假、雷军与小米、香港金融保卫战、保时捷与大众并购、赵薇资本博弈、娃哈哈治理、王一博与经纪公司资本关系。

本项目不复现或优化操纵、内幕交易、对敲、虚假申报等违法行为；不使用非公开信息；不绕过登录、验证码、付费墙或平台反爬限制。公开视频和公开图文只作为研究材料，不能据此给个人或公司下违法结论。

## 2. 核心概念

证据链的最小单位是“原子命题”，不是整条视频。

事实传导链回答：

```text
发生了什么 -> 通过什么机制 -> 引发了什么后续事件或结果
```

作者推理链回答：

```text
作者引用的前提 -> 作者的中间判断 -> 作者的结论
```

两条链必须分开保存。核验后的第三条链用于标记哪些事实成立、哪些关系被削弱、哪些地方存在替代解释。

## 3. 样本筛选

每条候选视频需满足：

1. 有明确人物、公司、证券、交易或政策事件。
2. 有相对清晰的时间窗口。
3. 能找到 UP 主本人或其官方渠道发布的完整图文稿；找不到时才使用字幕或 ASR 作为文本来源。
4. 至少包含三条可外部核验的命题。

排除纯宏观评论、没有具体事件对象的观点视频，以及只能依靠匿名传闻构建主要结论的视频。若样本不足，保留候选但在 `selection_status` 中说明原因，不用未经确认的转载替代官方稿。

## 4. 数据流

```text
公开视频/官方图文稿
        |
        v
原始材料归档（URL、BVID、标题、日期、抓取时间、哈希）
        |
        v
文本对齐（图文段落、字幕句段、视频时间戳）
        |
        v
原子命题抽取（事实、机制、推断、结论、未知）
        |
        +--> 事实传导链
        +--> 作者推理链
        |
        v
外部一手资料检索与交叉核验
        |
        v
核验链、争议表、可视化报告
```

文本来源优先级：官方图文稿 > 官方字幕 > 可访问的转载图文稿（仅作线索） > 本地 ASR。若使用 ASR，只保存研究所需的音频片段和时间戳，不保存完整视频文件。

## 5. 节点模型

节点类型：

- `F`：可核验事实，例如公告发布、交易发生、判决结果、持股变化。
- `M`：传导机制，例如强平压力、流动性冲击、控制权稀释、信息不对称。
- `I`：作者推断，例如“可能提前布局”“这是为了派发”。
- `C`：作者结论或概括，例如“绞杀国家队”“市值管理全链条”。
- `U`：传闻、缺证或无法判定的陈述。

每个节点至少包含：`claim_id`、`video_id`、`node_type`、`subject`、`predicate`、`object`、`event_time_start`、`event_time_end`、`quote`、`timestamp_start`、`timestamp_end`、`source_ref`、`source_grade`、`verification_status`、`notes`。

切分规则：

- 一个命题只保留一个主要主语、动作和对象。
- “所以、因此、说明、意味着、背后是、这就是”等连接词通常标记推理边，应拆成前提和结论。
- 数字、日期、主体、证券代码、公司名称单独保留，避免一个长句同时承载多个不可独立核验的事实。
- 时间先后不自动等于因果关系。

## 6. 关系模型

关系类型：`precedes`（先于）、`causes`（导致）、`triggers`（触发）、`amplifies`（放大）、`enables`（使得成为可能）、`supports`（支持）、`contradicts`（反驳）、`author_implies`（作者暗示）。

每条边至少包含：`edge_id`、`from_claim_id`、`to_claim_id`、`relation_type`、`origin`、`mechanism_text`、`evidence_refs`、`confidence`、`alternative_explanation`、`review_status`。

`origin` 取值：

- `explicit_author`：作者明确说出。
- `implicit_author`：根据上下文还原。
- `externally_supported`：外部资料支持该关系。
- `narrative_only`：仅为叙事连接，不能当作因果证据。

## 7. 来源与核验

来源强度使用 `S1–S5`，不与研究母题或主题标签混用：

- `S5`：判决书、行政处罚决定书、法律法规、交易所公告、公司正式披露。
- `S4`：政府统计、交易所行情、审计报告、正式研究报告。
- `S3`：具名采访或有明确来源链的专业媒体报道。
- `S2`：普通媒体、书籍、二次整理。
- `S1`：视频口播、匿名爆料、自媒体转载、无法追溯的传闻。

节点核验状态：`confirmed`、`partially_confirmed`、`unsupported`、`contradicted`、`disputed`、`unverifiable`。

核验原则：来源等级描述证据强度，不直接等同于命题真假；一份官方材料可能只证明交易发生，不能证明动机。每个事实节点必须附原文或视频时间戳，每个结论必须能回溯到至少一个前提；找不到材料时记录“未验证”，不能写成“虚假”。

## 8. 输出物

每条视频输出：

1. Markdown 事件概览。
2. 作者事实传导链。
3. 作者推理链。
4. 外部核验后的链。
5. 断裂边、争议边和替代解释。
6. 完整来源表。
7. Mermaid 关系图。

全局 CSV：

- `videos.csv`：视频、图文稿、抓取和版本信息。
- `claims.csv`：原子命题及证据定位。
- `edges.csv`：事实与推理关系。
- `sources.csv`：外部来源和访问状态。
- `review.csv`：核验意见、复核人、复核时间。

示例：

```text
F1 监管清理场外配资
  -> triggers M1 高杠杆账户触及平仓线
  -> amplifies F2 强制卖出增加
  -> amplifies F3 股价进一步下跌
  -> supports C1 作者关于“自激式踩踏”的结论
```

## 9. 异常处理与合规

- 图文稿不可访问：保留索引页、访问时间和失败原因，回退到官方字幕或 ASR。
- 文章与视频不一致：分别建立版本，不擅自合并。
- 视频删除、改标题或页面变化：以 BVID 为主键，保存抓取时间、URL 和内容哈希。
- 遇到验证码、登录墙、付费墙或反爬：停止自动请求并记录，不绕过。
- 争议性人名或公司指控：只描述公开材料能支持的行为，不把作者推断改写成事实。

## 10. 验收标准

首轮完成时应满足：

- 10 条视频均有可追溯的 BVID、标题、发布日期和文本来源。
- 每条视频至少形成一条事实传导链和一条作者推理链。
- 所有核心结论都有前提回溯路径。
- 每条“导致”边均有机制说明和来源/推理来源标记。
- 核心数字、日期、主体和证券代码完成外部核验或明确标为未验证。
- 任何模型生成的隐含关系都不会被标记为作者原话。
- 关键因果边人工复核，报告中列出断裂链和替代解释。
