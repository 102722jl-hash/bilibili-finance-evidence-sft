宏观2 · 巫师财经公开视频证据链与可审计宏观推理数据集

03路线演进：从采集底座到跨链推理数据集

设计文档（docs/superpowers）与导出集（exports/）共同记录了这条演进线。

08-07 证据链采集与抽取底座起点

确立"原子命题为最小单位"，落地公开 B 站页面采集、官方图文稿摄入、命题切分与关系构建、SQLite 存储、Markdown/Mermaid/CSV 报告。

为什么先做底座：没有稳定的原文快照与哈希，后面的核验和结论都没有可回溯的锚点。

08-10 多任务训练数据集扩展

在证据链之上增加多任务监督数据的构建管线（training/），把研究结构投影成可训练样本。

为什么加这一层：证据链本身是"研究产物"，必须再经过一次确定性投影才能变成"训练信号"。

08-11 事件案例包 v2结构化

把单条视频整理成"事件案例包"：案例模型、生成、导出、校验，形成可复用的案例单元。

为什么要案例化：散落的命题无法直接用于问答与展示，案例包提供了统一的容器与门禁。

08-12 对话式 QA v3 + v3 SFT 数据集 + 十案例复原收敛

引入对话式问答（qa/v3_*）与发布/校验环节，并把十个案例统一复原到同一规格。

为什么做对话式：证据边界天然是多轮追问的对象——"这个结论从哪条证据来""有没有替代解释"——对话结构比单轮更贴近真实审计。

v6 → v7 跨链推理导出当前成果

exports/ 依次沉淀 v6 首轮 / 二轮 / 推理完整，以及 v7-cross-chain-reasoning 跨链推理与预览版，并保留 90 条 V4.1/V2.3 兼容集与 UI 审计文件。

为什么保留多版本：数据集版本本身就是成果的一部分；兼容集与审计文件让"历史结论如何演进"可被复核。

04节点与关系模型

证据链的最小单位是"原子命题"，不是整条视频。

节点类型（五类）

F可核验事实：公告发布、交易发生、判决结果、持股变化
M传导机制：强平压力、流动性冲击、控制权稀释、信息不对称
I作者推断：如"可能提前布局"
C作者结论：如"绞杀国家队""市值管理全链条"
U传闻、缺证或无法判定的陈述

关系类型（八类）

  • precedes 先于 · causes 导致 · triggers 触发 · amplifies 放大
  • enables 使得成为可能 · supports 支持 · contradicts 反驳 · author_implies 作者暗示
  • 边的来源 origin：explicit_author / implicit_author / externally_supported / narrative_only
  • 每条边记录机制说明、证据引用、置信度与替代解释

来源强度 S1–S5

S5判决书、行政处罚、法律法规、交易所公告、公司正式披露
S4政府统计、交易所行情、审计报告、正式研究报告
S3具名采访或有明确来源链的专业媒体报道
S2普通媒体、书籍、二次整理
S1视频口播、匿名爆料、自媒体转载、无法追溯的传闻

核验状态

  • confirmed 已确认 · partially_confirmed 部分确认
  • unsupported 暂无支撑 · contradicted 被驳斥
  • disputed 存在争议 · unverifiable 无法核验
  • 核验原则：来源等级描述证据强度，不直接等同于命题真假；一份官方材料可能只证明交易发生，不能证明动机。

05关键设计决策：为什么这样做，而不是别的做法

下表是项目中最关键的取舍，每项对应一个被明确放弃的替代方案。

决策点采用方案放弃的替代方案为什么这样做
证据粒度 以"原子命题"为最小单位（一命题一主语一动作一对象） 以整条视频/整段为单元 整段无法独立核验，也无法定位到原文位置；拆成原子命题后，每条事实才具备"原文 + 定位 + 时间戳"三要素。
链的划分 事实传导链与作者推理链分开保存 合并成一条"因果链" 作者说了什么（推理链）与客观发生了什么（事实链）必须解耦，否则会把作者推断误当成已发生的事实。
时间与因果 时间先后不自动等于因果；仅有先后时生成 precedes 相邻即判因果 "随后发生"是最常见的伪因果来源；用 precedes 与 causes 区分，才能避免把叙事顺序当成因果证据。
隐含关系 模型还原的关系标为 implicit_author，置信度 low，待人工复核 直接标为作者原话 任何模型生成的隐含关系都不得伪装成作者明确表述，否则审计链会被污染。
缺证处理 找不到材料记 unverifiable（未验证） 写成"虚假" / 直接下结论 "未找到证据"与"证据表明为假"是两回事；把前者写成后者是对涉外个案的不实指控。
来源范围 仅使用公开材料；不绕过登录/验证码/付费墙/反爬 绕过限制抓取非公开内容 合规边界先于数据规模；遇到拦截就记录并停止，而不是硬闯。
媒体处理 ASR 仅作最后回退，只保存研究所需音频片段 优先转写、保存完整视频 官方图文稿信息最完整且可引用；保存完整视频既无必要也带来版权与体积负担。
结论纪律 每个结论必须能回溯到至少一个前提；关键因果边人工复核并列出断裂链与替代解释 只给最终结论 结论谱系（conclusion lineage）是可审计的核心：说不清"从哪条证据来"的结论一律不进入数据集。
旧产物处理 全部归档，绝不删除 直接删除 / 原地覆盖 路线纠偏过程本身是成果的一部分；保留归档让任何结论都能回溯到当时的中间态。

07验收证据（可复核）

以下为渲染验收脚本对 10 个案例的实测结论。

viewport: desktop 1440x1000  /  mobile 390x844

每个案例（共 10 个）:
  nodeCount        = 23      （万科控制权争夺为 24）
  laneStepCounts   = [8, 7, 8]
  qaCount          = 9
  hasVersion       = true
  hasAbstain       = true
  horizontalOverflow = false
  sourceCards      = 10 ~ 15

errors: []
→ 桌面端与移动端两套视口均无错误、无横向溢出
为什么把"存在证据边界（hasAbstain）"作为验收项之一？ 因为一个只会给确定答案的系统，恰恰无法表达"这里证据不足"。把弃权能力做成每个案例都必须具备的字段， 才能保证数据集在训练后仍然保留"承认不确定"的行为。
